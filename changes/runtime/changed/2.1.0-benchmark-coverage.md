# Close runtime benchmark coverage gaps before the 2.1.0 weights run

Adds the benchmark suites and hook accounting that `benchmark pallet --pallet '*'`
was silently skipping, so the 2.1.0 run on the reference machine produces measured
weights for them instead of carrying estimates forward:

- `frame_system_extensions`: registered in `define_benchmarks!`. Previously
  `frame_system::Config::ExtensionsWeightInfo` fell back to upstream's `()` impl,
  whose numbers come from Parity's reference hardware and RocksDB while this
  runtime uses ParityDb.
- `pallet_safe_mode`: registered in `define_benchmarks!`. The crate feature was
  already enabled but the pallet was never listed, so the runtime used upstream
  `SubstrateWeight`. Safe mode became load-bearing when it was made the
  failed-multi-block-migration handler.
- `pallet_version`: gains a `runtime-benchmarks` feature and an `on_initialize`
  benchmark. Its production `WeightInfo` returned `Weight::zero()` behind a TODO
  while the hook appends a digest log on every block; the interim fallback now
  reports that write.
- `pallet_c2m_bridge`: `on_initialize` now pre-accounts the storage write its
  `on_finalize` performs, matching `pallet_cnight_observation` and
  `pallet_partner_chains_bridge`. `on_finalize` cannot return weight, so the
  block budget has to reserve it in `on_initialize`.
- `pallet_cnight_observation::set_mapping_validator_contract_address`: benchmarked
  and moved onto `WeightInfo`; it was the one call in the pallet still priced by a
  hardcoded `DbWeight::writes(1)`.
