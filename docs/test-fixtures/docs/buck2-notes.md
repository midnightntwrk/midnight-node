# Building midnight-node with Buck2

An alternative build of midnight-node using [Buck2](https://buck2.build) +
[Reindeer](https://github.com/facebookincubator/reindeer), parallel to the
existing Cargo and Bazel builds. Stock buck2 and reindeer.

## Status

| Layer | State |
| ----------------------------------- | ----------------------------------------- |
| Third-party graph (`reindeer buckify`) | ◈ warning-free |
| Third-party crates (substrate, FRAME, ledger, consensus, service) | ◈ build |
| First-party libraries (all pallets, primitives, runtime-common) | ◈ build |
| `primitives/mainchain-follower` (sqlx offline) | ◈ builds |
| `runtime` (real on-chain WASM blob embedded) | ◈ builds; blob has 84 substrate exports, node builds a dev chainspec from it |
| `node` **library** | ◈ builds |
| `node` **binary** (`root//node:midnight-node-bin`) | ◈ builds, links, runs (`--version` → `midnight-node 2.0.0`) |
| `toolkit` **binary** (`root//util/toolkit:midnight-node-toolkit-bin`) | ◈ builds, links, runs |
| **tests** (`buck2 test //...`) | ◈ all pass except environmental (docker/devnet/Cardano) + a substrate-test-runtime blob; the real on-chain WASM blob is built (see WASM runtime) |
| **CI** (`.github/workflows/buck2.yml`) | ◈ self-hosted `tier:large` under a bazel-remote action cache; runs `buck2 build` (node/toolkit bins + runtime wasm) + `buck2 test root//... --exclude ci-infra` |
| `relay` binary | ✗ blocked on rs_merkle digest version (see below) |

```sh
buck2 build root//node:midnight-node-bin
$(buck2 build root//node:midnight-node-bin --show-output | awk '{print $2}') --version
```

Caveat: the embedded runtime is a `WASM_BINARY = None` stub, so this binary
compiles/links/runs but cannot yet run a real chain — building the on-chain
WASM blob is a separate no_std crate-universe phase (below).

## Toolchain

* **buck2** — the official `facebook/buck2` pinned release (`2026-06-01`), the
  same one CI installs and checksum-verifies (`buck2/Earthfile`). Stock buck2 is
  the supported path; a local `gilescope/buck2` build also works (it only adds
  unrelated DICE-persistence work).
* **reindeer** — upstream `facebookincubator/reindeer`, pinned to one rev
  (`Earthfile` `+buck2-reindeer`, `REINDEER_REV`): regenerate with that rev
  only - another reindeer diffs the graph, and the drift check (below) goes red.
  Two upstream gaps are patched into its output by `normalize-git-sources.py`
  (see "Reindeer fixes").

Install buck2 to `~/.cargo/bin/buck2`.

## Layout

```text
.buckconfig              root + prelude cells (fixups vendored, no external cell)
.buckroot
BUCK                     runtime-wasm-stub genrule, on-chain wasm blob target
toolchains/BUCK          system rust/cxx/python toolchains (abs clang paths)
third-party/
  reindeer.toml          global cargo_env + vendor=false (fixups vendored below)
  Cargo.toml             @generated: direct external deps of all members
  patches.toml           buck-specific [patch] overrides (proc-macro-crate)
  patched/               vendored patched crates (proc-macro-crate bazel fallback)
  fixups/                local fixups overriding/extending the shared set
  keys.json              @generated: (name,req,source) -> manifest key sidecar
  Cargo.lock             seeded from the workspace lock
  BUCK                   @generated by reindeer
<member>/BUCK            @generated by scripts/buck2/gen-first-party.py
```

`third-party/vendor/` is not used — `vendor = false` (sources fetched via
`http_archive`/`git_fetch`). Vendoring is impossible for this graph:
`sp-crypto-hashing 0.1.0` and `substrate-prometheus-endpoint` appear from both
crates.io and the polkadot-sdk git tag, which `cargo vendor` rejects.

## Regenerating

```sh
earth +buck2-regen                                 # pinned reindeer; writes the files back
REINDEER=target/release/reindeer scripts/buck2/regen.sh   # same steps, a local build of that rev
```

`regen.sh` runs, in order: `cargo metadata --locked`; `gen-third-party.py`
(reseeds `third-party/Cargo.lock` from the workspace lock - `regen.sh` deletes
it first, the script only seeds a missing one); `reindeer buckify`;
`normalize-wasm-stub-outdir.py`; `gen-wasm-deps.sh` (seeds its resolve and
`wasm-deps/Cargo.lock` from the workspace lock); `reindeer buckify` again;
`gen-first-party.py` for every member; `sync-test-fixtures.sh`. Both locks
derive from the workspace lock, so a `Cargo.lock` bump reaches both universes.

**Drift check.** CI (`buck2.yml` `regen` job, `earth +buck2-check-regen`) runs
the same regeneration on a snapshot and fails on any diff, naming the hunks:
a Cargo bump that skipped `earth +buck2-regen` cannot land a graph that builds
the old crates. Byte-reproducible by construction - the generators are
deterministic and the pinned reindeer and both seeded locks remove the inputs
that were not.

`normalize-wasm-stub-outdir.py` enforces `OUT_DIR == CARGO_MANIFEST_DIR` for the
two WASM-stub crates (`frame-storage-access-test-runtime`, `substrate-test-
runtime`): their fixups overlay a `WASM_BINARY = None` stub into the manifest dir
and set OUT_DIR there, but the `polkadot-sdk-<hash>` git-fetch cell hash in that
path moves on every polkadot-sdk bump while the static fixup hash doesn't — so
re-pinning by hand drifts (it did, twice). The normalizer rewrites the generated
BUCK so the hash self-heals. Idempotent; a no-op run exits 0.

### `normalize-git-sources.py`

Runs after each buckify. Upstream reindeer keys `git_fetch` on the repo URL, so
midnight-ledger's per-crate rc tags (15 commits of one repo, two versions of
`transient-crypto` among them) collapse onto one fetch and every crate builds
against whichever commit it pinned; it also sets `CARGO_MANIFEST_DIR` to the
repo root for a crate in a subdirectory, which breaks `proc-macro-crate`. The
script renames each git crate's fetch target to `<repo>-<urlhash><commit8>`,
points `CARGO_MANIFEST_DIR` at the crate's subdirectory and splits each
`git_fetch` into one per commit, matching rules to packages by name + version
from `cargo metadata`. Idempotent. Delete it once
facebookincubator/reindeer PRs 118 and 119 land.

### `gen-third-party.py`

Emits `third-party/Cargo.toml` from `cargo metadata`: every external (non-path)
normal+build dependency of any workspace member, features unioned. Key points:

* **Feature seeding** — buck2 builds each crate ONCE with a fixed feature set
  (no per-consumer selection like Cargo). Each entry is seeded with the feature
  set the crate resolves to in the *whole-workspace* build, so `std` /
  `fixed-point-custom-serde` etc. that first-party enables via propagation are
  on. Matching is by name + version-satisfies **only** (not source): a
  `[patch]`'d dep keeps its registry source in the dependency record while the
  resolved package is git, so a source filter would miss every patched
  midnight-ledger crate.
* **Multi-version keys** — a dep declared at genuinely distinct versions gets
  suffixed keys (`rand-0-8`); variants resolving to the same version are merged.
* **Rename collisions** — one package under several aliases (e.g.
  `substrate-prometheus-endpoint`) is merged to one key.
* **`[patch]` propagation** — workspace `[patch]` + `third-party/patches.toml`.
* **Standalone workspace** — the manifest has an empty `[workspace]` so Cargo
  doesn't fold it into the repo workspace; the lock is seeded from the repo lock
  so yanked-but-locked versions (e.g. `core2 0.4.0`) resolve.

### `gen-first-party.py`

Emits a `BUCK` per workspace member. Path deps → `root//<dir>:<name>`, external
deps → `root//third-party:<key>` (via `keys.json`). Renamed deps land in
`named_deps`. Features from the whole-workspace resolve. Build scripts are NOT
run; instead:

* **ENV_HOOKS** — compile-time env a `build.rs` would set:
  `ledger/helpers` (LEDGER_*_VERSION), `runtime` (OUT_DIR → wasm stub),
  `node` (SUBSTRATE_CLI_IMPL_VERSION).
* **SRCS_HOOKS** — non-`.rs` inputs: mainchain-follower's `.env` + `.sqlx`
  filegroup, mock-data-sources' `examples/`, res's config blobs.
* Default srcs glob is `src/**` (not just `*.rs`) so `include_str!`/
  `include_bytes!` of colocated data files are in the sandbox.
* **MAPPED_SRCS_EXTERNAL / EXPORTS** — a crate whose sources `include_str!`
  files ABOVE its own dir (the toolkit does `../../../COMPACTC_VERSION`,
  `../../../node/Cargo.toml`, `../../../res/test-contract/…`) can't resolve them:
  rustc resolves `include!` relative to the source file, but buck sandboxes srcs
  rooted at the target's package. Fix (as reindeer does for git crates): emit
  `mapped_srcs` that mirror the repo layout inside the package sandbox — own
  files at `<rel>/…`, external files (pulled cross-package via `export_file`
  labels) at their repo-relative paths — with `crate_root`/`CARGO_MANIFEST_DIR`
  prefixed by `<rel>`. The `../` includes then resolve against the mirror.
* Standard `CARGO_PKG_*` (incl. VERSION_MAJOR/MINOR/PATCH, AUTHORS) are set so
  the `frame_support::pallet` and clap `#[command(author)]` macros work.
* **Only normal deps** become link deps — dev- and build-only deps are skipped
  (buck doesn't run build scripts, so build-deps like `substrate-wasm-builder`
  must not become link deps).

## Notable per-crate handling

* **sqlx offline** (`mainchain-follower`) — sqlx-macros 0.9 verifies
  `query_as!` against the `.sqlx` cache, tried in order: `SQLX_OFFLINE_DIR`,
  `<manifest_dir>/.sqlx`, `<workspace_root>/.sqlx` (the last shells out to
  `cargo metadata`, which EOFs in the sandboxed `__srcs` tree). We hit
  candidate #2: the crate carries its **own real `.sqlx/`** (copied from the
  workspace-root cache), globbed into srcs so it stages like `src/*.rs` — a
  `__srcs` symlink to project source that the remote worker materializes.
  `CARGO_MANIFEST_DIR="."` is auto-absolutized by the rust prelude
  (`_DIRECTORY_ENV`) to the `__srcs` root, so `<manifest_dir>/.sqlx` resolves
  on local **and** RE without cargo metadata. A relative `SQLX_OFFLINE_DIR`
  missed (rustc's CWD is the repo root, not `__srcs`); a `$(location)` one
  missed too (that filegroup artifact isn't materialized at its logical path
  under remote execution — only srcs symlinked to project source are).
  `CARGO="cargo"` set for sqlx's pre-offline presence check.
  Caveat: the crate `.sqlx/` duplicates the root cache; keep them in sync
  (`cargo sqlx prepare --workspace` then re-copy) — CI `prepare --check` guards it.
* **proc-macro-crate** — 3.x invokes `cargo` to resolve `codec = { workspace =
  true }` renames, unavailable under buck. Patched with the same Cargo.toml-scan
  fallback the Bazel build uses (`third-party/patched/proc-macro-crate`, wired
  via `third-party/patches.toml`).
* **runtime WASM** — `substrate-wasm-builder` can't run under buck (spawns
  cargo). The runtime's `include!(OUT_DIR/wasm_binary.rs)` is fed a
  `WASM_BINARY = None` stub (`:runtime-wasm-stub` genrule). Same for
  `frame-storage-access-test-runtime` via a reindeer `overlay`. **The on-chain
  WASM blob is NOT built** — that needs a separate no_std crate-universe /
  wasm32 platform phase (as the Bazel build does with a transitioned target).

## Tests

`gen-first-party.py` emits `rust_test` targets: one **unit-test** per crate (the
lib recompiled with the test harness, running its `#[test]` fns) and one per
`tests/*.rs` **integration test**. These pull dev-dependencies — so
`gen-third-party.py` includes dev-deps in the third-party graph (`TEST_SRCS_HOOKS`
adds test-only data dirs like ledger's `test-data/`, db-sync's `testdata/`).

```sh
buck2 test "kind('rust_test', root//...)"   # or a single target
```

`buck2 test //...`: **all test targets build and run; 8 fail, all environmental**
— not buck-infrastructure gaps. Two remaining classes:

1. **Need the real on-chain WASM blob** (the runtime embeds a `WASM_BINARY=None`
   stub): `sc-partner-chains-consensus-aura`, `partner-chains-demo-node`. cargo
   passes these because wasm-builder builds the blob; that's the deferred no_std
   crate-universe phase.
2. **Need a devnet / docker / JS toolchain** (`test-images.docker-compose.yml`,
   a live node, postgres+db-sync, or Node/compactc): `util/toolkit` integration
   tests `single_tx`, `cached_context`, `toolkit_e2e`, `cli_tests` (trycmd);
   `partner-chains-cardano-offchain` integration tests; `partner-chains-db-sync`
   unit tests (postgres).

**Fixed** (previously environmental, now green):

* **CWD-relative fixture reads** — `res`, `docs`, `node`, and `util/toolkit`
  unit tests assumed cargo's CWD = crate dir (`CFG_ROOT="../"`, `../README.md`,
  `../docs/openrpc.json`, `../../res/...`). buck runs from the workspace root
  (`run_from_project_root=True`), so these `../` reads escaped above it. The
  paths now resolve CWD-independently by walking up to the `res/cfg/default.toml`
  anchor (`midnight_node_res::locate_workspace_root`, plus per-crate helpers) —
  correct under both cargo and buck.
* **toolkit `test-data/` fixtures** — read via `env!("CARGO_MANIFEST_DIR")`,
  which buck bakes to the sandbox `__srcs` dir. Added `midnight-node-toolkit:
  ["test-data/**"]` to `TEST_SRCS_HOOKS` so the fixtures land in the sandbox.
* **Windows-only third-party crates** (`winapi`, `ntapi`, `crossterm_winapi`,
  `hyper-named-pipe`) failed the compatibility check on macOS/Linux because
  reindeer factored their `cfg(windows)` `.lib` deps into base without inferring
  `target_compatible_with`. Local fixups under `third-party/fixups/<crate>/`
  mark them `target_compatible_with = ["config//os:windows"]`, so `//...` skips
  them cleanly (they never build off-Windows anyway). This eliminated the 4
  build failures.

`pallet-midnight-unit-test` is flaky (one nondeterministic test) — passes most
runs; a test-determinism issue, not a buck one.

## WASM runtime (done)

The real on-chain WASM blob is built end-to-end in buck2 (replacing the
`WASM_BINARY=None` stub): a parallel no_std build of the runtime's dependency
closure, cdylib-linked to wasm32, wasm-opt'd and zstd-compressed. `buck2 build
root//:runtime-wasm` produces a 1.1 MB blob (substrate `sp-maybe-compressed-blob`
format: 8-byte magic prefix + zstd), with 84 substrate exports (`Core_version`,
`Core_execute_block`, `Metadata_metadata`, `GenesisBuilder_build_state`, …). The
node embeds it and builds a dev chainspec from it. Mirrors the Bazel `crates_wasm`
universe. Infrastructure:

* **`wasm-deps/`** — the no_std crate universe. `scripts/buck2/gen-wasm-deps.sh`
  resolves `midnight-node-runtime` standalone with `default-features=false`
  filtered to `wasm32v1-none` (the exact no_std tree) and emits
  `wasm-deps/Cargo.toml`; a second `reindeer buckify` produces `wasm-deps/BUCK`
  (`root//wasm-deps:<crate>`), sharing the std universe's fixups. The resolve
  and `wasm-deps/Cargo.lock` are seeded from the workspace lock, so the blob is
  built from the versions cargo ships: unseeded, 42 crates had drifted to newer
  releases (`bytes`, `either`, `bitvec`, `generic-array`, ...).
* **`platforms/BUCK`** — `wasm32v1-none` platform (`os:none` + `cpu:wasm32`).
* **`toolchains/BUCK`** — the rust toolchain targets `wasm32v1-none` and passes
  `--cfg substrate_runtime` when `cpu:wasm32` is selected.
* **`.buckconfig`** `[build] execution_platforms` — host as the exec platform so
  build scripts compile+run on the host when cross-compiling to wasm.

### Host/target feature split — the core blocker, and how it's handled

The runtime is strictly no_std, yet crates like `either` and `memchr` are in
BOTH graphs: the no_std **target** (e.g. `either` via
`polkadot-ckb-merkle-mountain-range` ← `pallet-mmr`, all normal edges) and the
**host** (via `itertools` ← `aquamarine`, a proc-macro, which wants `std`). buck
builds each crate once. reindeer's per-platform resolver routes a proc-macro
*dependency* to the exec platform (`platforms_for_dependency`), but the `std`
*feature* a host proc-macro chain contributes still leaks onto the wasm32 base —
`cargo metadata`'s unified feature view can't distinguish it, and a workspace
`resolver` setting doesn't reach reindeer's custom resolver.

**Approach** (mirrors Bazel's explicit `wasm_aware_features`): since nothing in
the wasm runtime may use `std`, a per-crate `omit_features` fixup scoped to
`['cfg(target_arch = "wasm32")']` drops `std`/`use_std` on wasm32 while host/exec
builds keep them. Fixups live in `third-party/fixups/<crate>/` (shared with the
std universe via the `wasm-deps/fixups` symlink; harmless there — it never builds
wasm32). Done so far: `either`, `memchr`, `byte-slice-cast`, `once_cell`. A crate
that needs both a `buildscript`/`cargo_env` directive and a wasm32 `omit_features`
(`parity-scale-codec`, `serde`, `indexmap`, …) carries both in its one vendored
fixup file.

### Cleared

* **Feature split** — `either`, `memchr` now build for wasm32 (no_std base, std
  on exec dicts).
* **C-FFI for wasm** — `secp256k1-sys` compiles its vendored C for wasm32.
  Apple's `/usr/bin/clang` has no wasm backend; `toolchains/BUCK` selects
  Homebrew LLVM (`/opt/homebrew/opt/llvm/bin/clang`) when `cpu:wasm32`.
* **`proc-macro-crate` patch** — the buck-specific patched `proc-macro-crate`
  (needed so `#[derive(Encode)]` resolves the `codec = { package = ... }`
  rename) lives in `third-party/patches.toml`. `gen-wasm-deps.py` now merges it
  into `wasm-deps/Cargo.toml`, exposed via a `wasm-deps/patched` symlink (reindeer
  refuses path deps that escape the third-party dir).
* **resolver 2** — the generated wasm manifests set `[workspace] resolver = "2"`
  (a bare `[workspace]` defaults to resolver 1 regardless of edition).

**The external no_std closure builds for wasm32.** `buck2 build
root//wasm-deps:frame-support --target-platforms=root//platforms:wasm32v1-none`
**succeeds** — the heaviest closure crate, pulling most of the tree, with its
proc-macro/build deps transitioned to the host exec platform and target deps to
wasm32. The std-leak crates now all split via `omit_features` fixups: `either`,
`memchr`, `byte-slice-cast`, `once_cell`, `hashbrown`, `itertools`, `serde`,
`serde_core`, `serde_json`, `scale-info`, `parity-scale-codec`, `indexmap`,
`semver`, `libc`. (Note: `buck2 build root//wasm-deps: --target-platforms=wasm32`
*without* a real target root fails — it forces host-only crates like `proc-macro2`
and build scripts onto wasm32; only build through an actual wasm target so buck's
exec transition sends host tools to the host.)

### First-party wasm variants (task #11 — mechanism done)

Every first-party crate in the runtime's no_std closure now emits a `select()` on
`cpu:wasm32` for its `features`/`deps`/`named_deps`:

* `gen-wasm-deps.py` writes a sidecar `wasm-deps/first-party-wasm.json` — each
  closure crate's no_std feature set (from the wasm resolve).
* `gen-first-party.py` reads it plus the `wasm-deps/BUCK` target names, and for
  each closure-crate lib (not proc-macros — host-built) emits the wasm branch:
  the no_std feature set, `root//third-party:X` repointed to `root//wasm-deps:X`,
  and both std-only third-party deps (e.g. `frame-benchmarking`) and non-closure
  first-party deps (e.g. node-side `time-source`) dropped. First-party closure
  deps are kept as-is — buck's platform transition rebuilds them for wasm32 and
  they carry the same `select()`.

`buck2 build root//runtime:midnight-node-runtime
--target-platforms=root//platforms:wasm32v1-none` builds the **entire first-party
closure** for wasm32 — **BUILD SUCCEEDED**.

A dep is repointed to wasm-deps only if the dep's crate name is in the consumer's
wasm dep set (`sidecar["deps"]`), not merely if a wasm-deps target exists — so
std-only deps like ledger's `lazy_static` (pulled onto wasm32 only via a host
proc-macro's base dep) are correctly dropped.

### Blob assembly (task #12 — cdylib compiles, link is the last mile)

`gen-first-party.py` emits a `midnight-node-runtime-wasm-cdylib` target
(`preferred_linkage = "shared"`, `--cfg substrate_runtime`, always the no_std
wasm deps/features; gated by `WASM_CDYLIB`). Building its `[cdylib]` sub-target
for wasm32 **compiles the whole runtime and generates every substrate wasm
export** (`Core_version`, `Core_execute_block`, `Metadata_metadata`, the
runtime-API entrypoints …). The wasm32 rust link uses `rust-lld` (`toolchains/
BUCK` linker `select` on `cpu:wasm32` — clang++ can't parse rustc's `-flavor wasm
--export` args).

**Last mile:** the link fails because buck's `system_cxx_toolchain` infers
`linker_type` from the host OS (darwin) and emits darwin shared-lib flags
(`-install_name @rpath/….so`, `.so` naming) that rust-lld's wasm flavour
rejects. Needs a wasm-aware cxx toolchain (`linker_type = "gnu"`, `.wasm` naming,
no install_name) for `cpu:wasm32`. Then the remaining pipeline is mechanical
(blueprint: `../midnight-node/runtime/BUILD.bazel`):

* a `configured_alias` building the cdylib for wasm32,
* genrule: `wasm-opt -O0 --mvp-features --strip-dwarf --signext-lowering`, then a
  `wasm-compress` tool (zstd + the 8-byte substrate magic prefix `[82,188,83,118,
  70,219,142,5]`) ported from `../midnight-node/tools/wasm-compress`,
* genrule emitting `wasm_binary.rs` with `include_bytes!` of the blob, wired into
  the runtime's `OUT_DIR` in place of `runtime-wasm-stub`.

## Reindeer fixes

Three upstream gaps, each worked around in-tree so no fork is needed:

1. **Multi-commit git sources** — one `git_fetch` per repo URL, so
   midnight-ledger's per-crate tags collapsed onto one commit's sources
   (`transient-crypto 2.2.0` compiled against the 3.0.0 checkout). Patched by
   `normalize-git-sources.py`; upstream facebookincubator/reindeer PR 118.
2. **`CARGO_MANIFEST_DIR` for git-subdir crates** — the bare repo short-name
   instead of `<short-name>/<path-within-repo>`, so `proc-macro-crate` read
   the wrong `Cargo.toml`. Same script; upstream PR 119.
3. **`rustc_link_lib`/`rustc_link_search` default to false** — a build
   script's `cargo:rustc-link-*` is dropped unless a fixup says otherwise
   (deliberate: fbsource links native libs as Buck targets via `extra_deps`),
   so blst, lz4-sys, zstd-sys and friends compiled but never linked. The 13
   crates whose build scripts emit link directives set both in their fixup;
   upstream PR 117 adds a project-wide default.

## CI

`.github/workflows/buck2.yml` runs `earth --ci +buck2-ci` on the self-hosted pool
(`runs-on: [self-hosted, "tier:large"]`), modelled on midnightntwrk/season#44.
buck2 keeps no local action cache - a fresh daemon recompiles everything - so each
run goes through a **bazel-remote action cache** that persists across runs on the
buildkitd (shared via `--BUCK2_CACHE_ADDR` when the host offers one, else a per-job
sidecar). `buck2/Earthfile` installs the pinned buck2 + toolchain and writes the
`.buckconfig.local` that points `[buck2_re_client]` at the cache; `buck2/buck2-ci.sh`
drives build then test. Cold once, warm thereafter - no borrowed cores, no mesh.

The build selects `root//platforms:re-cache` (`platforms/defs.bzl`): local
execution + a remote **action cache** (`remote_cache_enabled=True`), so misses run
locally and upload. The distributed `re-exec` platform and the rebuck2 engine were
retired - the self-hosted runners have the muscle the free ones lacked.

**Toolchain.** The wasm blob build needs a wasm-capable clang and `wasm-opt`.
`buck2/Earthfile` `+INSTALL` installs a pinned rustc (+ `wasm32v1-none`),
`clang`/`lld`/`llvm`, `protobuf-compiler`, and a pinned binaryen v130, and asserts
`clang --print-targets` includes wasm. The wasm `cc`/`cxx`/`ar` come from
`read_config("wasm", …)`; the macOS default in `toolchains/BUCK` is Homebrew LLVM,
and CI overrides it with a **global** `-c wasm.cc=…` (a root-cell `.buckconfig.local`
doesn't reach the `toolchains` cell). `toolchains/wasm-lld.sh` locates rust-lld via
`rustc --print sysroot` (portable across OS/arch).

**Drift.** A second job, `regen`, runs `earth +buck2-check-regen` on every PR:
the pinned reindeer regenerates the whole graph and any diff fails the job (see
"Regenerating"). Fork PRs run it on a GitHub-hosted runner, never the fleet.

**Infra tests.** The handful of tests needing Docker/devnet/Cardano carry a
`ci-infra` label (`gen-first-party.py` `CI_INFRA_*` sets); CI runs `buck2 test

### Linux `-sys` / toolchain failures — root-caused + fixed

The full node + toolkit + wasm blob builds green on Linux (verified in an
`ubuntu:24.04` container, clang 18.1.3, matching CI). The two cc-rs ones hid
behind cc-rs capturing the compiler stderr and reprinting only its own "command
did not execute successfully" one-liner — buck showed an empty diagnostic.
Diagnosed by reproducing in the container and re-running the printed
`__cc_shim.sh` by hand. The others surfaced only once those cleared and the build
reached the blob assembly / final link.

* **`secp256k1-sys` wasm compile — buck2 cell-scoping.** The cc-shim exec'd
  `/opt/homebrew/opt/llvm/bin/clang` (the macOS default in `toolchains/BUCK`) →
  `FileNotFoundError` on Linux. A `[wasm] cc` override in `.buckconfig.local` is
  **root-cell-scoped**, but `toolchains/BUCK`'s `read_config("wasm", …)` runs in
  the `toolchains` cell, which doesn't see it (`buck2 audit config --cell
  toolchains wasm.cc` → empty). Fix: pass it as a **global `-c wasm.cc=…`** on the
  build/test commands (buck2/Earthfile `+BUCK2` `buck2_args`), which reaches every
  cell. (`-Qunused-arguments` + absolute clang in `wasm-cc.sh` were
  also needed once the right compiler is found.)

* **`openssl` version skew.** openssl-0.10's build script reads
  `DEP_OPENSSL_VERSION_NUMBER` / `DEP_OPENSSL_CONF` from openssl-sys's build
  script to pick version cfgs and `osslconf=` flags. Reindeer bakes those once,
  at buckify time, from the buckify host's openssl (Homebrew 3.5 on a Mac), but
  `vendored` (via str0m-openssl) builds OpenSSL 3.6.3 from source on every OS,
  so the baked values never match. `third-party/fixups/openssl/` pins both to
  the vendored 3.6.3 (`30600030`, the `NO_*` set its `./Configure` emits); the
  env block replaces reindeer's rather than merging, so every `NO_*` flag must
  be listed or openssl-0.10 references `EVP_idea_*` / `EVP_camellia_*` symbols
  the ffi omits. Unconditional on purpose: scoped to `cfg(target_os = "linux")`
  it also scoped the build-script wiring (`OUT_DIR`, `rustc_flags`) to the
  linux platform dicts, and macOS compiled openssl-0.10 with no cfgs at all -
  the 1.0.x path, `E0432` on `EVP_MD_CTX_create`.

* **`ittapi-sys` — build script omitted by default.** Without a fixup, reindeer
  omits the build script, so
  `jitprofiling.c` (defining `iJIT_NotifyEvent` / `iJIT_GetNewMethodID`) is never
  compiled. On Linux the node pulls `ittapi` via wasmtime's profiling and the
  final link fails `undefined symbol: iJIT_*`. Fix: local
  `third-party/fixups/ittapi-sys/` re-enables it (`[buildscript.run.env]` +
  `OPT_LEVEL`). macOS doesn't pull ittapi, so it's a no-op there.

* **`protoc` + `binaryen`.** The composite now installs `protobuf-compiler`
  (substrate's `sc-network*`/`litep2p` codegen protobufs via prost-build) and a
  **pinned binaryen v130** from GitHub instead of apt's v108 — the `runtime-wasm`
  blob genrule runs `wasm-opt … --signext-lowering`, which v108 rejects.

## Remaining blockers

* **`rs_merkle` digest version (relay binary)** — `rs_merkle-1` fails
  `[u8;32]: From<GenericArray<...>>`: a `generic-array`/`digest` multi-version
  mismatch in the merkle/digest stack. Needs the digest stack unified to one
  version for that consumer. Does not affect the node or toolkit binaries.
